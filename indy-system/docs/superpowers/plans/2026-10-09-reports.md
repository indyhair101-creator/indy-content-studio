# Reporting foundation and parallel delivery Implementation Plan

> Use executing-plans for shared foundation, then isolated agents for independent report modules. User approved continuous execution; do not stop for intermediate plan approval.

**Goal:** Implement the approved report checklist with truthful completion tracking.
**Architecture:** Typed report domain, backward-compatible persisted history, independent UI/provider modules, server-only credential access.
**Tech Stack:** Next.js 15, React 19, TypeScript, Vitest, existing Neon JSON dashboard snapshots.
**Spec:** ../specs/2026-10-09-reports-design.md

## Global constraints
Thai UI; Asia/Bangkok; no production database migrations during tests; no fake metrics; no credentials in source/state; preserve existing changes; all 68 checklist numbers retained.

## Review focus
Date boundaries and prior periods; missing versus zero; duplicate multi-platform content; closed-via-publication versus observed completed steps; old backups and competing saves.

## Task 1: Source baseline and report contracts
- [ ] Commit only current app source, tests, build support and docs, excluding secrets/generated files.
- [ ] Create managed worktree from explicit baseline commit.
- [ ] Create features/reports/report-types.ts and report-dates.ts; tests/report-foundation.test.ts checks Bangkok boundaries, inclusive ranges and previous equal-length period.
- [ ] Add report state validation and backward-compatible persistence with round-trip tests.
- [ ] Capture status transitions in the authoritative write path with tests for repeated saves, manual publication and legacy completed content.
- [ ] Run targeted tests and typecheck; commit shared contracts.

## Task 2: Team reports
- [ ] Create team-report-selectors.ts and components/TeamReportWorkspace.tsx; consumes DashboardState and ReportFilters, returns unique-content/team/step summaries.
- [ ] Filters, current vs prior period, owners, backlog, task navigation, known/unknown timing. Tests prove grouped counts and historical limits.

## Task 3: Content/video reports
- [ ] Create insight selectors and components/InsightsReportWorkspace.tsx; consumes normalized observations and filters.
- [ ] Build overview, content drilldown, comparisons, video metrics, retention and unavailable states; tests prove metric meaning and correct aggregates.

## Task 4: Data providers and imports
- [ ] Implement authenticated server endpoints/provider adapters; inspect existing credentials by variable names only; verify official API contracts before requests.
- [ ] Settings status, validated imports, identity matching, snapshots and partial failures; tests for auth, invalid inputs and provider errors.
- [ ] Verify actual account access before checking checklist items 10–12.

## Task 5: AI and saved reports
- [ ] Evidence-based recommendations, draft action, saved frozen reports, CSV and printable export; use existing AI integration if available.
- [ ] No model access means explicitly unavailable, not rules labeled AI.

## Task 6: Integration and verification
- [ ] Wire AppShell and home-page-view centrally, preserve worktrees' ownership.
- [ ] Targeted tests, full regression, typecheck and browser check; fresh review.
- [ ] Update checklist only with verified outcomes and remaining account prerequisites.
